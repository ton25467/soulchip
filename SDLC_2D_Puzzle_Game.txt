PART 1: ภาพรวมโครงการ (Project Overview)
================================================================================

  - ชื่อเกม: SoulChip (เกมแก้ปริศนาแนว 2D)
  - รูปแบบการเล่น: ผู้เล่นควบคุมตัวละครในมุมมอง 2D (Top-down) เพื่อแก้ปริศนา
    โดยการผลักวัตถุ (กล่อง, ชิปพลังงาน) ให้ตรงช่องสวิตช์ เพื่อเปิดประตูทางออก
  - ภาษาหลัก: Go (Golang) 1.26+
  - ไลบรารีเกม: Ebitengine v2 (มีจุดเด่นเรื่องความเร็ว น้ำหนักเบา และจัดดการกราฟิก 2D ได้ดี)

PART 2: ความต้องการของระบบ (System Requirements)
================================================================================

  1. ความต้องการทางฟังก์ชัน (Functional Requirements - สิ่งที่เกมต้องทำได้)
     - ผู้เล่นต้องเดินได้ 4 ทิศทาง (บน, ล่าง, ซ้าย, ขวา) ตามตาราง (Grid-based)
     - วัตถุในเกม (เช่น กล่อง) ต้องผลักได้ทีละ 1 ชิ้น และไม่สามารถผลักทะลุกำแพงได้
     - มีสวิตช์เปิด-ปิดประตู เมื่อมีวัตถุวางทับประตูก็จะเปิด เมื่อดึงออกประตูก็จะปิด
     - มีระบบ Undo ย้อนกลับสถานะก่อนหน้าได้ไม่จำกัด เพื่อความสะดวกในการลองผิดลองถูก
     - มีระบบ Restart ด่านปัจจุบันอย่างรวดเร็ว
     - มีระบบ Save/Load ความก้าวหน้าของการผ่านด่าน

  2. ความต้องการที่ไม่ใช่ฟังก์ชัน (Non-Functional Requirements - คุณภาพของเกม)
     - ตัวเกมต้องรันได้ลื่นไหลที่ 60 FPS บนเครื่องคอมพิวเตอร์ทั่วไป
     - กราฟิกและงานภาพ 2D ต้องมีความประณีต สวยงามเป็นเอกลักษณ์ (High-quality Stylized 2D Art)
     - มีระบบแสงเงา 2D แบบไดนามิก (Dynamic 2D Lighting & Shadows) และเอฟเฟกต์ Bloom/Glow เรืองแสงของวัตถุพลังงาน
     - มีระบบละอองเอฟเฟกต์ (Particle Effects) เพิ่มความสดใสและมิติของหน้าจอขณะเล่น
     - ขนาดไฟล์สำหรับเล่น (Binary) ต้องมีขนาดเล็ก ไม่เกิน 50 MB
     - ทรัพยากรทั้งหมด (ภาพ, เสียง, ด่าน) ต้องถูกฝังลงในไฟล์เกม (Asset Embedding)
     - เกมต้องสามารถบันทึกสถานะลงบนเครื่องผู้เล่นได้อย่างปลอดภัย

PART 4: แผนการพัฒนาทีละสัปดาห์ (Week-by-Week Development Plan)
================================================================================

นี่คือรายละเอียดการทำงานในแต่ละสัปดาห์ (รวม 24 สัปดาห์) เพื่อให้ทีมงานพัฒนาตามได้ทันที

────────────────────────────────────────────────────────────────────────────────
เฟสที่ 1: การวิเคราะห์และวางแผน (สัปดาห์ที่ 1 - 2)
────────────────────────────────────────────────────────────────────────────────

[สัปดาห์ที่ 1] : กำหนดแนวคิดและระบุขอบเขตเกม
  - งานที่ต้องทำ:
    1. ประชุมสรุปแนวเกม และกำหนดปริศนาหลัก (เช่น การต่อวงจรชิปพลังงาน)
    2. กำหนดทิศทางและสไตล์กราฟิกภาพ 2D ให้มีความสวยงามโดดเด่น (เช่น วางแผนใช้ภาพแนว Stylized Hand-drawn หรือ High-res Pixel Art ร่วมกับ Normal Map สำหรับสร้างมิติแสงเงา)
    3. ระบุข้อกำหนดขั้นต่ำของเครื่องผู้เล่น
  - ผลลัพธ์เมื่อจบสัปดาห์: เอกสาร Game Concept สรุปสั้น 1 หน้ากระดาษ พร้อม Mood board อ้างอิงสไตล์ภาพสวยงาม

[สัปดาห์ที่ 2] : ทำข้อกำหนดความต้องการ (Requirements) และร่างหน้าจอ UI
  - งานที่ต้องทำ:
    1. เขียนรายละเอียดคุณสมบัติเกมทั้งหมด (เดิน, ผลัก, สวิตช์, ประตู, บันทึก)
    2. วาดภาพร่างหน้าจอเกมหลัก (Wireframe) หน้าเมนู, หน้าเล่นเกม และหน้าเลือกด่าน
  - ผลลัพธ์เมื่อจบสัปดาห์: เอกสารข้อกำหนดเชิงเทคนิค และแบบร่าง Wireframe

────────────────────────────────────────────────────────────────────────────────
เฟสที่ 2: การออกแบบเชิงสถาปัตยกรรม (สัปดาห์ที่ 3 - 5)
────────────────────────────────────────────────────────────────────────────────

[สัปดาห์ที่ 3] : ออกแบบระบบความสัมพันธ์ของข้อมูล (Data & State Design)
  - งานที่ต้องทำ:
    1. ออกแบบไฟล์ด่านในรูปแบบ JSON (เช่น พิกัดเริ่มต้นของผู้เล่น, ตำแหน่งกล่อง, ผนัง)
    2. ออกแบบโครงสร้างประวัติสำหรับการย้อนกลับ (Undo Stack Struct)
  - ผลลัพธ์เมื่อจบสัปดาห์: ไฟล์โครงสร้างตัวอย่าง levels_example.json

[สัปดาห์ที่ 4] : ออกแบบงานศิลป์ (Art Design) และเตรียมกราฟิกชั่วคราว
  - งานที่ต้องทำ:
    1. ออกแบบภาพแนวคิดหลัก (Concept Art) ของตัวละครหลัก วัตถุผลัก (กล่อง/ชิป) และสิ่งแวดล้อมเพื่อคุมโทนภาพให้สวยงามประณีต
    2. วาดภาพตัวอย่างฉากเพื่อกำหนดเลย์เอาต์การจัดวางเลเยอร์พื้นหลัง (Background) และเลเยอร์วัตถุ (Foreground)
    3. จัดทำรูปภาพชั่วคราว (Placeholder) พร้อมโครงสร้าง Normal Maps สำหรับใช้พัฒนาระบบแสงเงาในโค้ดเกม
    4. วางแผนสไตล์เสียงประกอบ
  - ผลลัพธ์เมื่อจบสัปดาห์: ไฟล์ภาพ Concept Art, Asset List และภาพสำหรับทดสอบระบบภาพเบื้องต้น

[สัปดาห์ที่ 5] : วางแผนโครงสร้างโค้ดด้วยภาษา Go
  - งานที่ต้องทำ:
    1. ออกแบบ Interface และ Struct ในภาษา Go สำหรับแต่ละออบเจกต์ในเกม
    2. ออกแบบวิธีการเชื่อมโยงข้อมูลระหว่าง Scene (เปลี่ยนหน้าเมนูไปหน้าเล่นเกม)
  - ผลลัพธ์เมื่อจบสัปดาห์: ผังการเชื่อมโยงระบบโค้ด (Code Architecture Diagram)

────────────────────────────────────────────────────────────────────────────────
เฟสที่ 3: การเขียนโปรแกรมและการพัฒนาหลัก (สัปดาห์ที่ 6 - 15)
────────────────────────────────────────────────────────────────────────────────

[สัปดาห์ที่ 6] : ติดตั้งระบบและสร้างลูปหลัก (Go & Ebitengine Setup)
  - งานที่ต้องทำ:
    1. สร้างโปรเจกต์ `go mod init` และดาวน์โหลด Ebitengine v2
    2. เขียนโครงสร้างหลัก `main.go` ให้แสดงผลหน้าจอขนาด 640x480 พิกเซล
    3. สร้างระบบจัดการฉาก (Scene Manager) เพื่อสลับหน้าเมนูและหน้าเกม
  - ผลลัพธ์เมื่อจบสัปดาห์: โปรแกรมที่เปิดขึ้นมาแล้วแสดงผลหน้าต่างเกมเปล่าๆ ได้ที่ 60 FPS

[สัปดาห์ที่ 7] : ระบบแผนที่แบบตาราง (Grid Tile Map)
  - งานที่ต้องทำ:
    1. เขียนโค้ดอ่านไฟล์ JSON ของด่านเข้ามาเก็บในหน่วยความจำ
    2. เขียนส่วนการเรนเดอร์ภาพ โดยวาดกระเบื้อง (Tiles) ลงบนหน้าจอตามพิกัดตาราง
  - ผลลัพธ์เมื่อจบสัปดาห์: เกมสามารถแสดงแผนที่ด่านจำลองได้จากไฟล์ JSON

[สัปดาห์ที่ 8] : การเคลื่อนที่ของตัวละคร (Player Movement)
  - งานที่ต้องทำ:
    1. เขียนโค้ดรับค่าจากคีย์บอร์ด (ปุ่มลูกศร และ WASD)
    2. พัฒนาระบบตรวจสอบกำแพง (Collision Detection) ไม่ให้ตัวละครเดินทะลุผนัง
  - ผลลัพธ์เมื่อจบสัปดาห์: ตัวละครขยับตัวได้ทีละช่องตาราง และหยุดเดินเมื่อชนกำแพง

[สัปดาห์ที่ 9] : กลไกการผลักวัตถุ (Pushable Box Mechanic)
  - งานที่ต้องทำ:
    1. สร้างออบเจกต์กล่อง (Box) และระบบขยับกล่องเมื่อผู้เล่นเดินชน
    2. เขียนเงื่อนไขห้ามผลักกล่องพร้อมกันสองใบ และห้ามผลักกล่องทะลุผนัง
  - ผลลัพธ์เมื่อจบสัปดาห์: ผู้เล่นสามารถเดินไปผลักกล่องให้ขยับได้ตามกฎกติกา

[สัปดาห์ที่ 10] : ระบบสวิตช์และประตู (Switch & Door Mechanic)
  - งานที่ต้องทำ:
    1. เขียนระบบเช็กพิกัดตารางว่ากล่องถูกผลักไปทับตำแหน่งสวิตช์หรือไม่
    2. ผูกความสัมพันธ์หากกล่องทับสวิตช์ ให้ทำการเปลี่ยนสถานะประตูจาก "ปิด" เป็น "เปิด"
  - ผลลัพธ์เมื่อจบสัปดาห์: ผู้เล่นสามารถผลักกล่องทับปุ่มเพื่อเปิดประตูผ่านทางได้

[สัปดาห์ที่ 11] : หน้าจอเมนูหลักและหน้าเลือกด่าน (Menus & UI)
  - งานที่ต้องทำ:
    1. สร้างหน้าจอหลัก (เริ่มเกม, ออกจากเกม) รองรับเมาส์คลิกและคีย์บอร์ดเลือก
    2. พัฒนาหน้าจอแสดงด่านทั้งหมด และไฮไลต์ด่านที่ผู้เล่นปลดล็อกแล้ว
  - ผลลัพธ์เมื่อจบสัปดาห์: สามารถสลับด่านและเปิดเกมจากหน้าเมนูหลักได้

[สัปดาห์ที่ 12] : ระบบย้อนกลับ (Undo System) และเคลียร์ด่าน
  - งานที่ต้องทำ:
    1. เขียนโครงสร้างข้อมูลแบบ Stack เพื่อเก็บพิกัดของตัวละครและกล่องทุกครั้งที่เคลื่อนไหว
    2. เขียนโค้ดปุ่มย้อนกลับ (คีย์ Z หรือ R) เพื่อกู้สถานะก่อนหน้าขึ้นมา
    3. สร้างเงื่อนไขเมื่อตัวละครเหยียบช่องเป้าหมาย (Exit) ให้ถือว่าผ่านด่าน
  - ผลลัพธ์เมื่อจบสัปดาห์: ระบบย้อนหลัง 1 ก้าวได้ไม่จำกัดรอบ และเปลี่ยนไปด่านถัดไปเมื่อชนะ

[สัปดาห์ที่ 13] : ระบบบันทึกข้อมูลเกม (Save/Load System)
  - งานที่ต้องทำ:
    1. เขียนฟังก์ชันแปลงข้อมูลความก้าวหน้าของผู้เล่นให้อยู่ในรูป JSON
    2. บันทึกไฟล์ลงบนโฟลเดอร์สำหรับเก็บ App Data ของ OS (เช่น %APPDATA% ใน Windows)
    3. สร้างฟังก์ชันโหลดเกมอัตโนมัติเมื่อเปิดโปรแกรมใหม่
  - ผลลัพธ์เมื่อจบสัปดาห์: ปิดเกมแล้วเปิดใหม่ เกมจะจำข้อมูลด่านล่าสุดที่ผ่านได้

[สัปดาห์ที่ 14] : กลไกระดับสูง 1 - จุดเทเลพอร์ต (Teleporter)
  - งานที่ต้องทำ:
    1. สร้างกระเบื้องชนิดพิเศษ (Teleport Tile) เมื่อผู้เล่นหรือกล่องย้ายไปทับ ให้ส่งตัวละครไปยังอีกจุดหนึ่ง
    2. ป้องกันข้อผิดพลาดการเทเลพอร์ตซ้ำไปมาไม่สิ้นสุด (Cooldown System)
  - ผลลัพธ์เมื่อจบสัปดาห์: ปริศนาข้ามมิติทำงานได้ปกติ

[สัปดาห์ที่ 15] : กลไกระดับสูง 2 - พื้นน้ำแข็งลื่น (Slippery Ice Tile)
  - งานที่ต้องทำ:
    1. พัฒนาเงื่อนไขเมื่อเหยียบแผ่นกระเบื้องน้ำแข็ง ทั้งผู้เล่นและกล่องจะไถลต่อไปเรื่อยๆ จนกว่าจะเจอสิ่งกีดขวาง
    2. ปรับการทำงานของระบบบันทึกประวัติการเดิน (Undo) ให้สอดคล้องกับพฤติกรรมนี้
  - ผลลัพธ์เมื่อจบสัปดาห์: เพิ่มความซับซ้อนของการแก้ปริศนาด้วยพื้นน้ำแข็งลื่น

────────────────────────────────────────────────────────────────────────────────
เฟสที่ 4: การขัดเกลาและสร้างด่านจริง (สัปดาห์ที่ 16 - 19)
────────────────────────────────────────────────────────────────────────────────

[สัปดาห์ที่ 16] : ออกแบบด่านฝึกสอนและด่านทั่วไป (ด่านที่ 1 - 10)
  - งานที่ต้องทำ:
    1. สร้างด่านง่ายๆ เพื่อสอนวิธีเล่น ปุ่มควบคุม การผลักกล่อง และสวิตช์
    2. ค่อยๆ ปรับความยากขึ้นเล็กน้อยในทุกๆ ด่าน
  - ผลลัพธ์เมื่อจบสัปดาห์: ด่านจำลอง 10 ด่านแรกพร้อมให้ทดสอบความสนุก

[สัปดาห์ที่ 17] : ออกแบบด่านยากและปริศนาซับซ้อน (ด่านที่ 11 - 20)
  - งานที่ต้องทำ:
    1. นำระบบเทเลพอร์ตและพื้นน้ำแข็งลื่นมาเป็นตัวชูโรงในด่าน 11 เป็นต้นไป
    2. ลองให้คนอื่นในทีมทดสอบว่าด่านยากเกินไป หรือมีบั๊กที่ข้ามผ่านไม่ได้หรือไม่
  - ผลลัพธ์เมื่อจบสัปดาห์: ครบถ้วน 20 ด่านที่ออกแบบมาอย่างมีระบบระดับความยากที่เหมาะสม

[สัปดาห์ที่ 18] : นำเข้ากราฟิกจริงและพัฒนาระบบ Shader (Art Integration & Custom Shaders)
  - งานที่ต้องทำ:
    1. นำภาพกราฟิก 2D ที่วาดเสร็จสมบูรณ์อย่างสวยงามประณีต เข้าไปแทนที่ภาพจำลองชั่วคราวทั้งหมด
    2. พัฒนาระบบแสงเงา 2D (Dynamic Lighting) และแสงเรืองรอง (Bloom/Glow) บนชิปพลังงานและพอร์ทัลทางออก โดยเขียน Custom Shader (ภาษา Kage ใน Ebitengine)
    3. ปรับแต่งระบบ Particle Effects เพื่อเพิ่มรายละเอียดความอลังการของภาพ (เช่น ฝุ่นละอองฟุ้งรอบตัวละคร, สะเก็ดไฟเรืองแสงขณะเดิน, เอฟเฟกต์ฉลองตอนชนะด่าน)
    4. จัดทำแอนิเมชันเคลื่อนไหวที่นุ่มนวลและราบรื่น (Smooth Sprite Animation) ของตัวละครและปุ่ม UI (เช่น เอฟเฟกต์เฟด-เข้า/ออก ของปุ่มและหน้าเมนู)
  - ผลลัพธ์เมื่อจบสัปดาห์: ตัวเกมที่มีการแสดงผลหน้าจอกราฟิก 2D สวยงามสะดุดตาพร้อมเอฟเฟกต์พิเศษเรียลไทม์

[สัปดาห์ที่ 19] : ออกแบบและใส่ระบบเสียงประกอบ
  - งานที่ต้องทำ:
    1. ใส่เพลงพื้นหลัง (Background Music) เล่นวนลูปขณะเล่มเกม
    2. ใส่เสียงประกอบเอฟเฟกต์ (SFX) ตอนที่ผลักกล่อง, กดปุ่มสวิตช์, เดิน และชนะผ่านด่าน
  - ผลลัพธ์เมื่อจบสัปดาห์: เกมมีความสมบูรณ์ทางโสตสัมผัส

เฟสที่ 5: การทดสอบคุณภาพ (สัปดาห์ที่ 20 - 22)

[สัปดาห์ที่ 20] : เขียนชุดทดสอบการทำงานของโค้ด (Unit/Integration Test)
  - งานที่ต้องทำ:
    1. ใช้คำสั่ง `go test` เพื่อรันโค้ดจำลองทดสอบการชนของกล่องและผนัง
    2. ทดสอบว่าฟังก์ชันลื่นไถล และย้อนก้าวกลับ (Undo) ทำงานตามหลักคณิตศาสตร์ที่วางไว้
  - ผลลัพธ์เมื่อจบสัปดาห์: รายงานผลการทดสอบโค้ดผ่านเครื่องมือออโตเมชัน

[สัปดาห์ที่ 21] : ส่งให้กลุ่มผู้เล่นทดลองเล่น (Playtesting)
  - งานที่ต้องทำ:
    1. ส่งเกมให้ผู้ใช้งานภายนอกจำนวน 5-10 คนลองเล่นโดยไม่บอกวิธีเล่น
    2. บันทึกวิดีโอเพื่อดูพฤติกรรมว่าผู้เล่นสับสนกับ UI หรือระดับความยากเกินไปหรือไม่
  - ผลลัพธ์เมื่อจบสัปดาห์: เอกสารรวบรวมฟีดแบ็กและจุดที่ต้องปรับปรุงแก้ไข

[สัปดาห์ที่ 22] : แก้ไขข้อผิดพลาด (Bug Fixing) และ Optimize ประสิทธิภาพ
  - งานที่ต้องทำ:
    1. ไล่แก้บั๊กที่รวบรวมมา เช่น ปัญหากล่องติดมุมกำแพงแล้วขยับไม่ได้
    2. รันโปรแกรม pprof เพื่อวิเคราะห์ว่าเกมกินแรมหรือซีพียูส่วนเกินหรือไม่
  - ผลลัพธ์เมื่อจบสัปดาห์: ตัวเกมเวอร์ชันสุดท้ายที่เสถียรและไร้ข้อผิดพลาดร้ายแรง

เฟสที่ 6: การจัดเตรียมและเปิดตัวเกม (สัปดาห์ที่ 23 - 24)

[สัปดาห์ที่ 23] : คอมไพล์เกมข้ามแพลตฟอร์ม (Cross Compilation & Asset Embed)
  - งานที่ต้องทำ:
    1. ใช้ความสามารถ `go:embed` ฝังไฟล์ assets ลงใน Go binary เพื่อให้ได้ไฟล์รัน `.exe` ตัวเดียว
    2. สั่งคอมไพล์โปรแกรมสำหรับ Windows, macOS, และ Linux
  - ผลลัพธ์เมื่อจบสัปดาห์: ไฟล์ตัวเกมแบบสมบูรณ์พร้อมเล่นสำหรับทั้ง 3 แพลตฟอร์มหลัก

[สัปดาห์ที่ 24] : ปล่อยตัวเกมสู่สาธารณะและสรุปผลงาน
  - งานที่ต้องทำ:
    1. อัปโหลดไฟล์เกมขึ้นบนเว็บไซต์ itch.io หรือสร้างหน้า GitHub Releases
    2. ตรวจสอบการดาวน์โหลดและติดตั้งจากเครื่องเล่นภายนอกอีกครั้ง
  - ผลลัพธ์เมื่อจบสัปดาห์: เกม "SoulChip" เปิดให้บริการอย่างเป็นทางการบนระบบอินเทอร์เน็ต

  │ TC-09 │ ผ่านเข้าทางออกขณะประตูเปิดอยู่   │ เกมจะทำการเปลี่ยนด่านขึ้นด่านใหม่  │

PART 6: การปล่อยเกมและการดูแลรักษา (Deployment & Maintenance)
================================================================================

  1. คำสั่งสำหรับ Build ตัวเกมของภาษา Go:
     - ระบบ Windows:
       $ GOOS=windows GOARCH=amd64 go build -ldflags="-s -w" -o soulchip.exe main.go
     - ระบบ macOS:
       $ GOOS=darwin GOARCH=amd64 go build -ldflags="-s -w" -o soulchip main.go
     - ระบบ Linux:
       $ GOOS=linux GOARCH=amd64 go build -ldflags="-s -w" -o soulchip main.go

  2. การบำรุงรักษาหลังการขาย:
     - ติดตามการแจ้งเตือนบั๊กจากหน้าบอร์ดรีวิวของ itch.io
     - อัปเดตตัวเกมเพื่อให้รองรับระบบปฏิบัติการ OS เวอร์ชันใหม่ปีละ 1 ครั้ง
     - หากมีการแก้ไขข้อผิดพลาดทางเทคนิค ดำเนินการออกตัวอัปเดตย่อย (เช่น v1.0.1)
